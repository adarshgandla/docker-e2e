STEP 3
Write Backend Multi-Stage Dockerfile
backend/Dockerfile

Create backend/Dockerfile with layer caching & dev/prod targets:

backend/Dockerfile 
# 1. Base & Dependency Layer
FROM node:20-alpine AS base
WORKDIR /app
COPY package*.json ./
RUN npm ci

# 2. Development Stage (Live coding via bind mounts)
FROM base AS development
ENV NODE_ENV=development
COPY . .
EXPOSE 4000
CMD ["npm", "run", "dev"]

# 3. Production Stage (Lean non-root runner)
FROM node:20-alpine AS production
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 4000
CMD ["node", "src/server.js"]
💬 What to say to colleagues: "Notice we copy package*.json and run npm ci BEFORE copying our code. This allows Docker to cache all installed packages. Editing code won't trigger re-installation!"
STEP 4
Write Frontend Multi-Stage Dockerfile
frontend/Dockerfile

Create frontend/Dockerfile (Vite dev server + Nginx production server):

frontend/Dockerfile 
# 1. Base & Dependencies
FROM node:20-alpine AS base
WORKDIR /app
COPY package*.json ./
RUN npm ci

# 2. Development Stage (Vite Dev Server)
FROM base AS development
COPY . .
EXPOSE 3000
CMD ["npx", "vite", "--host", "0.0.0.0", "--port", "3000"]

# 3. Production Stage (Build React & serve with Nginx)
FROM base AS build
COPY . .
RUN npm run build

FROM nginx:alpine AS production
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
💬 What to say to colleagues: "In production, we don't keep Node.js running for static React files. We compile with Node, throw Node away, and copy dist/ into a 25MB Nginx web server!"
STEP 5
Write Root docker-compose.yml
docker-compose.yml

In the project root (focused-darwin/), create docker-compose.yml:

docker-compose.yml 
version: '3.8'

networks:
  app-network:
    driver: bridge

volumes:
  postgres_data:
  redis_data:

services:
  # 1. Database (PostgreSQL 16)
  postgres:
    image: postgres:16-alpine
    container_name: task_postgres
    environment:
      POSTGRES_USER: taskuser
      POSTGRES_PASSWORD: taskpass123
      POSTGRES_DB: taskflow
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./scripts/init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - app-network

  # 2. Cache (Redis 7)
  redis:
    image: redis:7-alpine
    container_name: task_redis
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    networks:
      - app-network

  # 3. Express Backend API
  api:
    build:
      context: ./backend
      target: development
    container_name: task_api
    environment:
      PORT: 4000
      DATABASE_URL: postgresql://taskuser:taskpass123@postgres:5432/taskflow
      REDIS_URL: redis://redis:6379
    ports:
      - "4000:4000"
    volumes:
      - ./backend:/app
      - /app/node_modules
    depends_on:
      - postgres
      - redis
    networks:
      - app-network

  # 4. React Frontend
  frontend:
    build:
      context: ./frontend
      target: development
    container_name: task_frontend
    ports:
      - "3000:3000"
    volumes:
      - ./frontend:/app
      - /app/node_modules
    depends_on:
      - api
    networks:
      - app-network
💬 What to say to colleagues: "Notice DATABASE_URL uses '@postgres:5432', not localhost. Inside Docker's virtual bridge network, containers reach each other by service name through Docker's internal DNS."
STEP 6
The Big Launch: Start All Services
Terminal

Execute in your terminal at project root:

Terminal (PowerShell) 
docker compose up --build
Watch for these exact green logs:

Clean Teardown & Reset
Terminal

When finished presenting, cleanly stop the containers:

Terminal 
# Stop all containers (data in volume is preserved)
docker compose down

# Or wipe everything fresh including database data
docker compose down -v
